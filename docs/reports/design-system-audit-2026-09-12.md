# Application-wide design-system audit

Date: September 12, 2026

## Verdict

**The application is partially aligned, but it does not yet meet the requirement that every page follow the same shared component patterns.** The shared palette, neutral border aliases, shell, and most shadcn primitives are connected correctly. Component state selectors, feature CSS, and several custom controls still bypass or undermine that foundation.

The previous completion statement was too broad: updating tokens and documentation did not establish complete component conformance. This audit found **9 systemic issues: 3 P1 major and 6 P2 minor**, with no P0 findings. These are grouped root causes, not counts of affected elements.

Scope: all **14 registered page implementations**, their local component dependencies, shared UI, feature CSS, and configuration. The source inventory parsed **145 TypeScript files, including 81 TSX files**. Counts describe source call sites, not runtime elements generated by loops.

This is a source, installed-package, and compiled-CSS audit. Fresh browser validation was not performed because access was previously denied by the browser URL policy. Responsive behavior and visual appearance therefore remain unverified in this audit. No application fixes were made.

## Current component architecture

The intended inheritance is sound: shadcn/Radix primitives → branded local components and global tokens → reusable application compositions → page content and layout.

| Area | Actual implementation | Assessment |
| --- | --- | --- |
| Theme | `app/src/styles/index.css`, Tailwind semantic aliases | Shared brand colors, border aliases, radii, and typography exist. Feature overrides still interfere. |
| Base UI | Local `components/ui` files; shadcn `radix-nova` configuration; `radix-ui` behavior | Correct foundation; some state and orientation selectors do not match Radix. |
| Buttons and fields | Shared Button, Input, SearchInput, Checkbox, Switch, Select | Most modules reuse them. Overview retains native alternatives; Select has no active feature consumer. |
| Navigation | Shared AppShell, Sidebar, Topbar, TanStack Router links | Centrally owned across authenticated routes and the preview. A specialized account trigger and skip link are valid shared compositions. |
| Tabs and filters | Shared Radix Tabs in Moderation, Drafts, Publishing; shared faceted filter in DataGrid | Overview uses separate filter-button styling. Shared Tabs orientation styling has a defect. |
| Status | Badge → TonePill/StatusPill/PriorityPill | Widely reused; Overview overrides badge internals and duplicates health-state styling. |
| Tables | TanStack React Table for DataGrid behavior; shadcn Table for rendering | Six operational pages use DataGrid. Plans and Coach use the simpler DataTable wrapper. Both render the same Table primitives. Overview uses those primitives directly. |
| Charts | Recharts | Most operational charts use ChartFrame, chart-theme, and ChartTooltip. Overview has separate presentation helpers. |
| Forms | Shared Input/Switch inside native React form/label compositions | A native form is appropriate. Two Coach textareas duplicate field styling; there is no shared Textarea primitive. `react-hook-form` is installed but not imported by app source. |

**TanStack and Recharts do not need replacing to achieve consistency.** Their behavior/rendering can stay behind the application's shared table and chart presentation APIs. Uniformity depends on those adapters and tokens, not on every component carrying a shadcn name.

## Prioritized findings

### F1 · P1 · Shared state styles target attributes Radix does not emit

Category: implementation integrity / theming / responsive behavior.

Locations: [Switch](D:/projects/Nx/NxClip/Admin/app/src/components/ui/switch.tsx:20), [Tabs](D:/projects/Nx/NxClip/Admin/app/src/components/ui/tabs.tsx:19), [Separator](D:/projects/Nx/NxClip/Admin/app/src/components/ui/separator.tsx:18), [Dialog](D:/projects/Nx/NxClip/Admin/app/src/components/ui/dialog.tsx:40), and the related Sheet/DropdownMenu/Select/Tooltip wrappers.

Verified against the installed Radix package and the current production CSS:

| Component state | Rendered Radix attribute | Selector generated by current classes |
| --- | --- | --- |
| Switch on | `data-state="checked"` on root and thumb | `[data-checked]` |
| Switch off | `data-state="unchecked"` | `[data-unchecked]` |
| Horizontal tabs/separator | `data-orientation="horizontal"` | `[data-horizontal]` |
| Open dialog/menu | `data-state="open"` | `[data-open]` |

The Switch's track color and thumb movement cannot follow its checked state. Tabs lose intended orientation-dependent sizing/layout. The faceted-filter Separator does not receive its orientation-dependent width. Several overlay enter/exit and open-state styles cannot activate. Event handlers and ARIA state may still work; this finding concerns the mismatch in the style contract.

`data-active` already has a correct custom mapping in [global CSS](D:/projects/Nx/NxClip/Admin/app/src/styles/index.css:39), so active-tab color is not the same defect. ScrollArea has the orientation issue too, but currently has no application consumer.

Recommendation: use explicit `data-[state=…]` and `data-[orientation=…]` variants, including group variants, or define equivalent shared aliases. Add meaningful checked/unchecked, orientation, disabled, and overlay-state checks to the component gallery and regression suite. Suggested command: `$impeccable harden`.

### F2 · P1 · Overview CSS overrides every shared PanelHeader

Category: implementation integrity / theming.

Location: [Overview base CSS](D:/projects/Nx/NxClip/Admin/app/src/features/overview/design/base.css:52).

The unscoped `[data-slot="panel-header"]` rule sets `padding: 17px 18px 0` and `gap: 10px`. It conflicts with [PanelHeader](D:/projects/Nx/NxClip/Admin/app/src/components/panel.tsx:29), which owns `px-5 py-4 gap-3`. This unlayered feature rule wins over the Tailwind utilities. Overview is eagerly imported by the router, so the rule is loaded application-wide rather than only after visiting Overview.

Impact: changing the shared header's spacing does not reliably update pages. Settings, configuration tables, chart headers, and the guide inherit an Overview-specific override, including zero bottom padding.

Recommendation: remove the global feature selector. Express an approved compact header as a shared PanelHeader variant, and keep feature selectors limited to composition. Suggested command: `$impeccable polish`.

### F3 · P1 · Shared table row actions have no keyboard equivalent

Category: accessibility / implementation integrity.

Locations: [DataGrid row](D:/projects/Nx/NxClip/Admin/app/src/components/data-grid.tsx:243), [DataTable row](D:/projects/Nx/NxClip/Admin/app/src/components/data-table.tsx:72).

Both wrappers attach `onClick` to a plain table row without a focusable row action or keyboard handler. Reviewed cells on the affected routes are text, badges, and avatars; they do not provide an equivalent inspect/edit button. DataGrid checkboxes select rows for bulk actions and stop click propagation, so they do not substitute for opening an inspector.

Impact: keyboard users cannot open the row inspector on the six DataGrid pages or select a different plan/category for editing on the two configuration pages. Overview already provides real inspect buttons, demonstrating the inconsistent table interaction contract.

Recommendation: add an explicitly named, focusable inspect/edit action through the shared table API, while retaining row-click convenience. Keep bulk selection distinct. Also give the shared sort-header control the normal DS focus treatment and expose current sorting on the header; neither is currently explicit. Suggested command: `$impeccable harden`.

### F4 · P2 · Overview bypasses controls and overrides component internals

Category: theming / implementation integrity.

Locations: [Overview controls](D:/projects/Nx/NxClip/Admin/app/src/features/overview/pages/overview-page.tsx:147), [analytic sections](D:/projects/Nx/NxClip/Admin/app/src/features/overview/components/dashboard-sections.tsx:17), [feature CSS](D:/projects/Nx/NxClip/Admin/app/src/features/overview/design/base.css:108).

Each Overview route reaches 11 native button call sites, two native checkbox call sites, and a native chart-window select. Four of the button sites and the chart select are shared between the two routes. The preview adds a second select. These are source counts; filters and table rows produce additional runtime instances.

Concrete differences:

- Checkbox color uses `--brand-violet`; shared Checkbox uses `--primary`. Desktop Overview boxes are 12px; the shared primitive is 16px. Overview changes its boxes to 16px in its mobile CSS.
- Plain controls use a 2px outline; the shared primitives use the 3px `ring-ring/50` treatment.
- Filter buttons use a separate active fill and type scale rather than a shared segmented-control variant.
- `.example-table [data-slot=badge]` forces 10px/400 text and its own padding. Shared Badge uses 12px/500 by default or the declared compact variant.
- `.example-creator [data-slot=avatar]` forces 26px sizing, bypassing UserAvatar's size API.
- Operational metric badges are custom spans with their own radius and opacity recipes.

Impact: editing Button, Checkbox, Badge, UserAvatar, or Select centrally will leave these instances partly unchanged. Sharing color variables alone is not full component conformance.

Recommendation: promote the approved compact appearances into shared variants; migrate equivalent controls to them. Use a shared segmented filter for filtering, and a shared section-navigation pattern for in-page anchors. Anchors should remain links rather than becoming ARIA tabs without tab panels. Suggested command: `$impeccable polish`.

### F5 · P2 · The same down service uses different status tones

Category: theming / semantic consistency.

Locations: [OverviewHealth](D:/projects/Nx/NxClip/Admin/app/src/features/overview/components/overview-health.tsx:27), [Overview state color](D:/projects/Nx/NxClip/Admin/app/src/features/overview/design/base.css:133), [System Health](D:/projects/Nx/NxClip/Admin/app/src/features/health/pages/health-page.tsx:25).

Overview maps `service.ok === false` to `is-degraded`, whose text and dot use warning amber, while labelling the service “Down.” System Health maps the same false state to danger/destructive via TonePill. The Overview summary also reuses the custom warning indicator.

Impact: the same API state communicates a different severity depending on the page. The health indicator bypasses the established shared status mapping.

Recommendation: centralize service-state → label/tone mapping and render shared status components. Preserve the preview's genuinely degraded fixture as a separate state. Suggested command: `$impeccable colorize`.

### F6 · P2 · Coach textareas duplicate a different field treatment

Category: theming / implementation integrity.

Locations: [CategoryEditor](D:/projects/Nx/NxClip/Admin/app/src/features/config/components/category-editor.tsx:207), [NewCategoryDialog](D:/projects/Nx/NxClip/Admin/app/src/features/config/components/new-category-dialog.tsx:177).

The same native textarea class recipe is repeated twice: transparent fill, `rounded-md`, fixed `text-sm`, and locally written focus rules. Shared Input uses a secondary fill, `rounded-lg`, mobile 16px text, and centralized disabled/invalid treatments. Both radius values happen to be 8px today, but their token roles can diverge later. There is no shared Textarea primitive to propagate changes.

Impact: multiline fields look and evolve differently from the other fields. Labels are present; the problem is duplicated presentation and state handling, not the use of native forms.

Recommendation: create one themed Textarea based on the same field contract as Input. Share label/help/error composition where repeated, including associating the slug validation hint with its input. Adopting a new form library is not required. Suggested command: `$impeccable harden`.

### F7 · P2 · Charts use the same renderer but not one presentation contract

Category: theming / implementation integrity.

Locations: [shared chart theme](D:/projects/Nx/NxClip/Admin/app/src/components/chart-theme.ts:8), [shared tooltip](D:/projects/Nx/NxClip/Admin/app/src/components/chart-tooltip.tsx:35), [Overview charts](D:/projects/Nx/NxClip/Admin/app/src/features/overview/components/dashboard-sections.tsx:77), [Explore tooltip](D:/projects/Nx/NxClip/Admin/app/src/features/explore/components/wes-scatter-chart.tsx:36).

Most operational charts reuse ChartFrame, AXIS_PROPS, GRID_PROPS, and ChartTooltip. Overview instead declares local axes, uses a `3 4` grid dash instead of `3 3`, uses an opaque elevated cursor instead of the shared muted cursor, and renders a separate `.example-tooltip`. Explore appropriately needs custom tooltip content but repeats the tooltip surface recipe too. Shared axis/legend font sizes and numeric bar radii are not connected to named typography/radius tokens.

Impact: updating the common chart tooltip, axis style, or chart typography does not propagate everywhere. Some current colors coincide because aliases resolve to the same value; that does not establish shared ownership.

Recommendation: keep Recharts; expose shared chart frame, axis/grid/cursor presets, tooltip surface, legend, and formatters. Let charts supply their content and data semantics. Define chart-specific geometry centrally instead of forcing every chart to have the same data layout. The old `signup-trend-chart.tsx` and `cohort-paid-chart.tsx` already use shared helpers but are not reachable from current pages; they were excluded from active-page compliance counts. Suggested command: `$impeccable polish`.

### F8 · P2 · shadcn configuration points at a missing stylesheet

Category: implementation integrity / maintenance.

Location: [components.json](D:/projects/Nx/NxClip/Admin/app/components.json:8).

`tailwind.css` points to `src/index.css`, which does not exist. The application imports `src/styles/index.css` from `src/app/main.tsx`.

Impact: the running app still gets its theme, but future shadcn generation/update operations are configured against the wrong CSS destination and can fail or write outside the intended theme owner.

Recommendation: point the configuration to the real shared stylesheet and preserve the brand overrides when introducing components. Suggested command: `$impeccable harden`.

### F9 · P2 · Current audits do not enforce component conformance

Category: implementation integrity / maintenance.

Location: [ds-audit.mjs](D:/projects/Nx/NxClip/Admin/app/scripts/ds-audit.mjs:101).

The audit checks raw hex colors and theme-variable declarations in feature CSS, but not unscoped shared-component selectors, numeric typography, or component-internal overrides. Its TSX rules do not inspect native control adoption or Radix state compatibility. Most rules exclude base primitives, and the Design System page is excluded entirely. The bundled Impeccable static detector also returned zero findings for this tree.

Impact: a passing audit currently means the implemented checks passed; it cannot certify that every component on every page follows the design system. All other findings in this report coexist with a green audit.

Recommendation: add focused enforcement for feature overrides of shared slots, unsupported primitive state selectors, duplicate control recipes, and the real shadcn CSS path. Keep justified native compositions on an explicit allowlist. Add behavioral tests for shared control states and keyboard table actions. Suggested command: `$impeccable harden`.

## What to preserve

- One shared shell and one root theme, including root-level colors for portaled content.
- Global border aliases for panels, fields, tables, sidebar, and overlays.
- Shared Button, Input, Badge, StatusPill, and table primitives already used by most modules.
- TanStack's table behavior and Recharts' chart rendering; these are compatible with the desired architecture.
- Explicit loading/unavailable/empty data handling, chart sample disclosures, and preview fixture labelling.
- Valid specialized compositions: the shared account-menu trigger, native form elements, skip link, in-page anchors, and content-specific chart semantics are not defects merely because they are not standalone shadcn components.

## Recommended implementation order

1. **P1 — `$impeccable harden`:** repair Radix state/orientation selectors and shared keyboard row actions, with focused regression checks.
2. **P1/P2 — `$impeccable polish`:** remove the global PanelHeader override and move approved compact controls, badge sizing, and avatar sizing into shared APIs; migrate Overview consumers.
3. **P2 — `$impeccable colorize`:** unify health-state tones through a common mapping.
4. **P2 — `$impeccable harden`:** add the shared multiline-field contract, correct the shadcn stylesheet path, and strengthen enforcement.
5. **P2 — `$impeccable polish`:** consolidate chart presentation and finish with a bounded desktop/mobile and control-state verification pass once browser access is allowed.

The changes should be organized by shared component families, with consumer migrations where necessary. Rebuilding pages independently would recreate the current problem. Rerun `$impeccable audit` after the fixes.
